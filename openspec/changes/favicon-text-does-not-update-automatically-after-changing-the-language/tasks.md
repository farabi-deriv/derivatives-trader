## Open Questions

Each is answered with a RECOMMENDED default and the plan proceeds on that basis — none blocks implementation. A reviewer may substitute their own answer; the affected tasks are named so the swap is mechanical.

**Q1. Does "favicon text" in issue #951 mean the browser tab label (`document.title`), or the favicon image itself?**

- **(a) RECOMMENDED — the tab label, i.e. `document.title`.** The screenshot and video on the issue show the browser tab, and the tab label is the only language-dependent thing there: the app ships one static icon set (`packages/core/build/config.js:66-70` copies a single `favicon.ico` plus fixed-size PNGs; `:234-259` injects the `<link>` tags) with no per-language variant, and no code path swaps it. `document.title` _is_ language-dependent and _is_ demonstrably stale. Whole plan as written.
- (b) The favicon image should carry per-language artwork. Would be a new feature, not a bug fix (new assets, a runtime `<link rel="icon">` swapper, a cache-busting strategy), and nothing in the issue or the repo suggests such assets exist. Reject unless QA confirms a per-language icon was ever shipped.
- (c) Both. Costs (b)'s work on top of (a); only worth it if (b) is confirmed.

**Q2. Where does the `document.title` write belong — render phase (as today) or `useEffect`?**

- **(a) RECOMMENDED — keep the write in the render phase**, inside the shared hook. React runs effects child-first, so an effect-based write inverts nested-router precedence and makes `/reports/statement` read "Reports | Deriv" instead of "Statement | Deriv" (design.md D2). Tasks 3.x as written.
- (b) Move to `useEffect` and add an explicit precedence protocol (e.g. the inner router marks the title as "owned" and the outer one skips when a deeper writer has claimed the current path). More idiomatic React, materially more machinery, and a new cross-package contract between `@deriv/core` and `@deriv/reports`. Would replace tasks 2.2, 3.1-3.3 and add a coordination task plus tests for the precedence protocol.
- (c) `useEffect` with no precedence handling. Rejected — a known regression on all four reports pages.

**Q3. Subscribe to `languageChanged` explicitly, or rely on `useTranslations()` re-rendering its callers?**

- **(a) RECOMMENDED — subscribe explicitly** on the i18next `instance` returned by `useTranslations()`. Makes the fix's mechanism legible, independent of react-i18next's `bindI18n` default, and unit-testable with a fake emitter (design.md D3). Requires task 1.3 (extend the shared translations mock).
- (b) Rely on the implicit re-render: simply calling `useTranslations()` in the route components is enough in production, because it wraps `useTranslation()` whose default `bindI18n: 'languageChanged'` force-updates consumers. Smaller diff, no mock change — but the fix becomes "call a hook and discard its result", which reads as dead code and is one upstream default away from silently regressing. If chosen: drop tasks 1.3 and 2.3, and reduce 2.4 to `useTranslations();` with a comment.
