## ADDED Requirements

### Requirement: [CSN-008] The cleanup guardrails are re-verified, not re-implemented

Before Workstream C closes, the safety net C0 installed SHALL be re-verified as still wired and still blocking: `knip:check` and `baseline:check` SHALL both be present as root npm scripts and both SHALL run as CI steps that fail the build on drift, and `baseline:check` SHALL still report the bundle-size delta against the committed bundle baseline. No replacement gate SHALL be built and no existing gate SHALL be loosened. Stale references to packages Workstream C deleted SHALL NOT remain in the CI workflow or in code ownership: a `tsc` project, test-matrix entry or ownership rule naming a package that no longer exists is removed.

#### Scenario: Both gates are still wired and blocking

- **WHEN** the root package manifest and the CI workflow are inspected
- **THEN** `knip:check` and `baseline:check` exist as scripts, each runs as its own CI step whose non-zero exit fails the job, and neither has been replaced or made advisory

#### Scenario: The bundle delta is still reported

- **WHEN** `baseline:check` runs
- **THEN** it reports the bundle-size delta against the committed bundle baseline as informational output, and still exits non-zero on structural set drift

#### Scenario: No CI reference to a deleted package survives

- **WHEN** the CI workflow and the code-ownership file are grepped for packages Workstream C deleted
- **THEN** no `tsc` project, test-matrix entry or ownership rule names one, and the workflow's remaining steps are otherwise unchanged

### Requirement: [CSN-009] knip:check runs the workspace-pinned knip, never an arbitrary resolution

The dead-code gate SHALL execute the knip version this repository pins and installs, so that a run is always compared against a baseline generated by the same major. It SHALL NOT invoke a resolution that can silently download and run a different version when the pinned binary is missing from the workspace. When the pinned binary cannot be resolved, the gate SHALL fail with a message naming the missing tool and how to install it, rather than producing a finding set from a different major. Baseline regeneration SHALL use the same resolution as the check, so the two can never diverge.

#### Scenario: The pinned binary is used when present

- **WHEN** the gate runs in a workspace where the pinned knip is installed
- **THEN** it executes that installed binary and diffs its findings against the committed baseline

#### Scenario: A missing binary fails loudly instead of fetching another version

- **WHEN** the gate runs in a workspace where the pinned knip is absent
- **THEN** it exits non-zero with a message identifying the missing tool and the install step, and no version is downloaded or executed

#### Scenario: Check and regeneration resolve identically

- **WHEN** the baseline is regenerated and the check is then run in the same workspace
- **THEN** both resolve the same binary, and the check reports no drift

### Requirement: [CSN-010] The architecture documentation matches the shipped store graph and carries the growth-stopping rule

The repository's agent-facing architecture documentation SHALL describe the store graph that actually ships: every root store member listed SHALL exist, no member SHALL be listed that Workstream C deleted, and no store SHALL be omitted. The same documentation SHALL carry the growth-stopping rule that keeps the cleanup from being undone — a new derived value is a `computed`, never an observable kept in step by a reaction; a new field has exactly one writer — stated where contributors already read the project's gotchas.

#### Scenario: Every documented root store member exists

- **WHEN** the documented root-store member list is compared against the root store's constructor
- **THEN** the two sets are equal — no documented member is absent from the code and no constructed member is missing from the documentation

#### Scenario: The growth-stopping rule is documented

- **WHEN** the project's gotchas are read
- **THEN** they state that a new derived value must be a `computed` rather than an observable plus reaction, and that a new field must have exactly one writer
