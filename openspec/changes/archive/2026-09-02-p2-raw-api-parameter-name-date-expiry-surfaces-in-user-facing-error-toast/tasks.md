## Open Questions

None blocking. Assumptions taken autonomously while planning (all recorded in `design.md` — Decisions):

1. **The reported toast is the `MissingEither` mapping.** `mapErrorMessage`'s `MissingEither` case renders `'Please specify either {{param_1}} or {{param_2}}.'` from `code_args`, which reproduces the reported string exactly for `['duration', 'date_expiry']`. The identical string could also arrive as raw `error.message` on the unmapped path, so both paths are fixed rather than guessing which one the reporter hit.
2. **`date_expiry` → "end time"**, matching the app's own **End time** duration tab (`AppV2/Components/TradeParameters/Duration/chips.tsx:29`, `duration-unit-selector.tsx:27`) rather than inventing "expiry date".
3. **`amount` is deliberately left out of the glossary** — its meaning flips with `basis` (stake vs payout), so a fixed label would be wrong half the time.
4. **An unmapped message with an _unlabelled_ identifier is replaced by the generic message.** Chosen over leaking the identifier; the raw message stays on the error object for logging.
5. **The Gold/USD duration blocker is out of scope** — this change makes the rejection readable whether or not it still occurs, per the issue's own framing.
