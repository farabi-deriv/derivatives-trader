## Why

The ~13.6k-LOC store layer still carries dead remnants after the C1–C2 extraction cleanup ([#1268](https://github.com/deriv-com/derivatives-trader/issues/1268)): three near-duplicate `BaseStore` copies (core JS, reports JS, trader TS), a `trade-store` V1/V2 gate (`is_dtrader_v2`) that now returns a constant plus a dead WebSocket layer, dead forward-starting/session trade helpers, and dozens of orphaned members across the core and reports stores — alongside two latent reports defects and a call to an already-removed client-store method. This is issue [#1270](https://github.com/deriv-com/derivatives-trader/issues/1270) (Workstream C dead-code cleanup, tracking [#1019](https://github.com/deriv-com/derivatives-trader/issues/1019)), the second destructive pass gated on the C0 safety net ([#1267](https://github.com/deriv-com/derivatives-trader/issues/1267)) and C1–C2. It removes ~2,200 LOC of proven-dead store code (re-verified member-by-member at HEAD) so the store layer reflects only what ships, and shrinks the merge surface for the M1/S1 redesign work.

## What Changes

- **C5a — consolidate `BaseStore`.** Promote the trader TS `BaseStore` into `@deriv/stores` as the single shared base (at `packages/stores/src/base-store.ts`, exported from `src/index.ts`), repoint all real-`BaseStore` subclasses in core/reports/trader at it, and delete the two byte-divergent JS copies (`packages/core/src/Stores/base-store.js`, `packages/reports/src/Stores/base-store.js`). Break the trader-local `getValidationRules` **type** coupling by generalizing the base's validation-rules type; add `@deriv/shared` as a `@deriv/stores` dependency; keep the existing generic `BaseStore<T>` (`packages/stores/src/stores/BaseStore.ts`, used by `FeatureFlagsStore`) untouched. Strip the dead theme-listener machinery (`onThemeChange`/`disposeThemeChange`/`themeChangeDisposer`/`theme_change_listener`) plus the dead `this.disposeThemeChange()` call at `trade-store.ts:3390`. Carry core's `retrieveFromStorage` declared-keys filter into the consolidated store so it never reads an undefined storage key (fixes the `getItem(undefined)` bug present in **both** JS copies). `onRealAccountSignupEnd`/`disposeRealAccountSignupEnd` are already gone at HEAD (verify absent).
- **C5b — `trade-store.ts` deep-clean (~180 LOC).** Collapse the always-`true` `is_dtrader_v2` getter (`2750`) and its 11 gates (removing the getter/registration **last**), drop the equivalent `processPurchase` `is_dtrader_v2` parameter and the unreachable `useGuideContractTypes` arm; delete the dead WS layer (`wsSubscribe`/`wsForget`/`wsForgetStream`/`wsSendRequest` + `g_subscribers_map`, `3443–3535`) with its orphaned type imports; remove the dead members `is_synthetics_available`, `is_synthetics_trading_market_available`, `getFirstOpenMarket` (+ `findFirstOpenMarket` import), the `setMobileDigitView`/`is_mobile_digit_view_selected` pair and the `setIsDigitsWidgetActive`/`is_digits_widget_active` pair; de-duplicate the barrier-validation-error clearing where safe.
- **C5c — trader helpers (~330 LOC).** Delete the fully-dead whole files `multiplier.ts` and `preview-proposal.ts` (+ their tests + the `preview-proposal` knip-baseline entry); collapse the forward-starting/session dead logic in `contract-type.ts` (`getSessions` stub, `getValidTime`, the `getExpiryTime` session branch, `getStartDates`/`start_dates_list`) and the neutered rule sets + dead `isSessionAvailable` import in `validation-rules.ts`; trim the dead `dateFrom`/`dateTo` members in `positions-store.ts` and the `favoriteIndicators`/`favoriteSymbols`/`syncLocalStorage` cluster in `markets-store.ts` (+ their `mockStore.ts` mirror).
- **C5d — core stores (~630 LOC).** Remove the dead ui-store modal/flow clusters (~48 members incl. the legacy `pwa_prompt_event` pair) + their `types.ts`/`mockStore.ts` mirrors; the portfolio-store hover-barrier chain (`onHoverPosition` → `updateTradeStore` → `setPurchaseSpotBarrier`/`updateLimitOrderBarriers`) and its unreachable branch; the remaining dead members in client-store (`setPreferredLanguage`), notification-store (dead configs), common-store (platform cluster: `routeTo`/`isCurrentLanguage`/`showError` + write-only `platform`/`app_router`/`was_socket_opened`), the contract stores (write-only `sell_info`/`is_static_chart`/`is_chart_scaling`), and dead `Helpers` (`device.js`, core-duplicate `getBuyPrice`); de-duplicate the cross-store sell flow; and remove the now-orphaned calls to the already-removed `client.setPreventRedirectToHub`/`setExternalParams`.
- **C5e — reports stores (~50 LOC) + two defects.** Remove the dead `account_statistics`, `filtered_date_range` and phantom `suffix_icon` members (+ `useReportsStores.tsx` type mirrors + tests); fix `handleFilterChange`'s wrong `{}` default (a reset must restore "all transactions"); and fix the statement icon's `key` to read the row's real identifier (`refid`, not the absent `transaction_id`).

**Non-goals (explicitly kept live / out of scope):** demo top-up (`resetVirtualBalance`→`topupVirtual`, `reset_virtual_balance` notification), `is_try_real_modal_visible`/`toggleTryRealModal`, portfolio `barriers`/`barriers_flattened`/`is_empty`/`is_multiplier`, ui-store `prompt_when`/`promptFn` and `deferred_prompt`/`notifyAppInstall`, `chart-markers.js`/`chart-marker-helpers.js`, and the whole theme system — all verified live. The `archived-statement.tsx` `useState` consolidation (~150 LOC) is **flagged for a follow-up** (deferral filed), not done here.

## Capabilities

### New Capabilities

- `base-store-consolidation`: The contract for C5a — a single shared `BaseStore` in `@deriv/stores`, every subclass repointed with identical runtime behavior, the two JS copies deleted, the dead lifecycle/theme machinery stripped, and `retrieveFromStorage` guaranteed never to read an undefined key.
- `reports-store-fixes`: The contract for C5e's two user-visible defect fixes — an argument-less statement filter reset restores "all transactions", and each statement transaction icon carries a stable React key from the row's real identifier.

### Modified Capabilities

- `store-member-cleanup`: Extend the C2 store-surgery contract with the C5 store-member removals — `trade-store` (`is_dtrader_v2` collapse, dead WS layer, dead members), core stores (ui-store clusters, portfolio hover-barrier chain, remaining client/notification/common/contract/Helpers members, cross-store sell-flow dedup), trader positions-/markets-stores, and reports stores — all under the same `\bmember\b`-grep verification and green-gate discipline.
- `dead-code-removal`: Extend the C1 whole-unit-deletion contract with the dead trader helper files (`multiplier.ts`, `preview-proposal.ts`) and the forward-starting/session dead-logic collapse in `contract-type.ts`/`validation-rules.ts`.
