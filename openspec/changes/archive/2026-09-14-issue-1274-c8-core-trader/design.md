## Goals / Non-Goals

**Goals:**

- Delete only what is provably unreachable, proven per symbol by repository-wide grep rather than by a tool's exit code.
- Land in ordered phases that each build, test and lint green on their own, so an interrupted multi-run leaves a coherent branch and a bisect lands on a working tree.
- Finish `packages/core` outright before starting `packages/trader`, so an interruption ships one whole half.
- Retire the stale alias map in every place it is actually declared — which is not where the issue says it is.
- Leave both committed baselines regenerated, so the next change inherits an accurate gate.
- Leave behind two package-local guard specs that pin the KEEP set, so the next sweep cannot delete `getByMsgType` on a grep.
- Report every stale claim explicitly rather than deleting something else to match a number.

**Non-Goals:**

- Editing `packages/shared`, `packages/components`, `packages/reports`, `packages/api`, `packages/stores` or `packages/utils`. Both parents have in-flight PRs.
- Fixing `login-button.tsx`'s `TS2339`, or the `Cannot find module 'Stores/…'` errors that `packages/core`'s tsconfig produces for `packages/trader` and `packages/reports` sources. Both are real, both are separate changes.
- Fixing the broken CI `Check TypeScript` step. Already filed by C7 at `docs/spec-to-pr/deferrals/ci-typescript-gate-is-a-no-op.md`; not re-filed.
- Deleting `packages/core/src/public/images/common/static_images/migration-onboarding-*.png` (2.0 MB) or the `Images` alias, or restoring the two missing banner images. All deferred.
- Deleting `front-channel.html` or `language-link.tsx`. Both deferred, for different reasons.
- Following up items 1–3 of `docs/spec-to-pr/deferrals/components-prop-prune-core-consumers.md` (tracked as #1373). This change _unblocks_ three of its four core-only props by deleting their sole consumers (`dev-tools/mock-dialog.tsx`, `toggle-settings.jsx`, `toggle-notifications.jsx`), but the matching `@deriv/components` edits live in that package.

## Decisions

### D1 — Prove deadness per symbol; treat `knip:check` as a formality

For each symbol: grep the name **word-bounded** across the whole repository excluding `node_modules`, `.git` and `dist` — so `__mocks__/`, `scripts/`, `playwright/`, `build/`, every `.scss` and every `.js`/`.jsx` file are included — then _read_ every hit. A hit that is the symbol's own definition, spec or barrel line is not a consumer. A hit inside the same module makes the symbol internally live: de-export, keep the implementation.

This is what caught `getContractPath` being shadowed by `@deriv/shared`'s, `BinaryLink` being live in core while its `packages/reports` namesake was deleted last change, and `AccumulatorStats` (singular, live) sitting next to `AccumulatorsStats` (plural, dead). None of those would surface in a knip exit code.

_Alternative rejected:_ trusting `npm run knip:check` plus the CI type step. Both are structurally blind here.

### D2 — Two type oracles, stated as separate shrinking-or-equal numbers

```
trader   0   total errors
core   277   total error TS lines
        26   non-test
         1   under packages/core  → login-button.tsx(34,13) TS2339
        23   under packages/trader (alias resolution)
         2   under packages/reports (alias resolution)
```

Gating on core's _total_ would make this change responsible for 25 errors it did not cause and cannot fix without editing another package. Gating on core's _own_ count (1) makes any regression unambiguous and attributable. Both numbers are recorded and both are gated at `≤`.

_Alternative rejected:_ fixing the path mapping so `packages/core`'s tsconfig stops pulling in trader/reports source. It is a real defect, it would change the number this change is measured against mid-flight, and it belongs with a tsconfig change, not a 11,500-line deletion.

### D3 — Phase order, chosen so each phase is independently green and core finishes first

Cheapest-and-safest first, whole-file deletions before in-file edits, SCSS last within each package, all of core before any of trader:

1. **Pre-flight** — record both oracles, both baseline exits, both dependency counts.
2. **C8b-assets** — fonts, `presets-onboarding/`, `plus.svg`, orphan SVGs, and the `Fonts`/`Translations` alias entries in `build/constants.js` + `knip.json`. Mechanical, independently verifiable, and it is the phase that moves `roots.core`.
3. **C8b-deps** — the 15 removals and the two `devDependencies` moves. Independent of any source edit.
4. **C8b-files** — the notification chain, the Footer, `dev-tools/`, `LogoutSuccessModal/`, the Elements orphans, the templates loaders, `_common/lib/`, the two 0-byte files, the cookie banner. Whole-file deletions.
5. **C8b-edits** — the in-file work: `Routes/helpers.ts` and the named exports, the `binary-routes` regex, `notification.jsx`'s `case 'news'`, `utility.js`'s dead pair, `authorizeAccount`'s de-export, PWA `unregister`, `Constants/currency.js`.
6. **C8b-scss** — `account-common.scss` and the rest, under the base-class rule.
7. **C8b-guard** — `packages/core/src/__tests__/dead-code-sweep.spec.ts`, then `knip:baseline`. **Core is complete here.** If the run stops after this phase it has shipped one whole half.
8. **C8c-assets** — `src/public/` and the three `tsconfig.json` alias entries.
9. **C8c-build** — `build/helpers.js`, `generateSWConfig`/`htmlOutputConfig`, the `is_test_env` eslint block, `.eslintrc.ts`, the `index.d.ts` shim.
10. **C8c-files** — the TradeTypes cluster, the trade-categories tree, the orphan survivors, the runtime-dead modules.
11. **C8c-deps** — the 6 removals plus `@types/react-beautiful-dnd`, after their importers are gone.
12. **C8c-scss** — last, because `contract-type-info.scss` is only dead once phase 10 has landed.
13. **C8c-guard + baselines** — `packages/trader/src/__tests__/dead-code-sweep.spec.ts`, `build:all`, `knip:baseline`, `baseline:update`.

_Alternative rejected:_ interleaving core and trader by category (all assets, then all deps, then all files). It reads tidier but leaves both packages half-swept at every stopping point, which is exactly what the multi-run protocol exists to prevent.

### D4 — The stale alias map is retired where it is declared, not where the issue says

Four config surfaces were checked for each package. The map is not in three copies; it is in one place for trader and two for core:

| Declaration                         | `packages/trader`               | `packages/core`                            |
| ----------------------------------- | ------------------------------- | ------------------------------------------ |
| `tsconfig.json` `paths`             | **Fonts, Images, Translations** | —                                          |
| `build/constants.js` `ALIASES`      | — (7 roots)                     | **Fonts, Images, Translations**            |
| `jest.config.js` `moduleNameMapper` | —                               | —                                          |
| repo-root `knip.json` `paths`       | — (no `paths` block)            | **Fonts, Images, Images/\*, Translations** |

Consequences: the trader deletion touches exactly one file and moves no baseline; the core deletion touches two and moves `roots.core`, which is what `baseline:update` is for. `Images` is **kept** on the core side — `src/public/images/` is live (favicons, `logos/platform_logos/`, `static_images/`, all copied by `build/config.js` and read through `getUrlBase`) — even though no source imports through the alias. Removing a live directory's alias is a separate judgement from removing a dead directory's.

### D5 — `packages/shared`'s guard spec is a hard constraint, and the answer is to defer, not to edit

`packages/shared/src/__tests__/dead-code-sweep.spec.ts` reads two `packages/core` paths with `fs.readFileSync`. For `_common/utility.js:60` this costs nothing — `isEuCountry` is live anyway. For `App/Components/Routes/language-link.tsx:54` it is decisive: the file has exactly one consumer (its own barrel line) and would otherwise be a clean delete, but removing it turns a `packages/shared` spec red, and Part 3 rule 8 forbids editing that package. The named export is dropped; the file stays; the deletion is deferred with the coupling recorded.

_Alternative rejected:_ editing the shared spec to drop the assertion. It is one line and trivially correct — and it would put this PR in conflict with #1272's in-flight PR over a file neither change owns. That is precisely the collision rule 8 exists to prevent.

### D6 — The `front-channel.html` gate is discharged by deferring, not by assuming

The issue makes "verify no OIDC registration references it" a hard gate. In-repo evidence is unambiguous — zero OIDC references, one CopyPlugin entry — but the thing that would reference it is an **external identity provider's** registered front-channel-logout URI, which no amount of grepping this tree can settle. A gate that cannot be discharged is not the same as a gate that passes. The file and its CopyPlugin entry stay; a deferral names exactly what an operator must check (the IdP client's `frontchannel_logout_uri`) and what to do when they have.

### D7 — De-export rather than delete where a symbol is internally live

Three symbols have zero external references but a live internal caller. Deleting them breaks the module; leaving them exported keeps a dead public surface. They lose the export and keep the implementation:

| Symbol                                                            | Internal reader                                                                                       |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `socket-general.authorizeAccount`                                 | called at `socket-general.js:90`, defined at `:167`                                                   |
| `Routes/helpers.ts` `normalizePath` / `findRouteByPath`           | `binary-link.tsx:23-24` — kept **exported**, since the consumer imports them across module boundaries |
| `_common/utility.js` `isEuCountry`                                | `getRegion` in the same file (and the shared guard spec)                                              |
| unreferenced named exports of `Config/trade-parameter-presets.ts` | the module's four production importers                                                                |

### D8 — SCSS is validated by the build, but only after the base class is proven

`npm run build:all` is the strongest SCSS gate here: sass-loader hard-fails on an undefined mixin or variable. It cannot catch a deleted **class** still produced by string interpolation or emitted by the chart library. So the rule is: identify the base, grep the base, delete only then; never delete on a modifier grep; never delete `cq-*` / `stx-*` / `sc-*` / `ciq-*`.

Two live examples in this sweep's own path: `.trade-container` looks like a v1-form-only base but `contract-replay.tsx:97` renders `trade-container__replay`; and `contract-type-info__content-definition` / `__video` are referenced by `Categories/Description/*` and `contract-type-description-video.tsx`, so `contract-type-info.scss` is live _until_ DCR-043 lands. That coupling is why SCSS is last, not merely why it is careful.

Note that C8b claims ~2,470 dead SCSS LOC out of core's 4,884 — roughly **half** of core's stylesheets. That is aggressive. Every core SCSS deletion needs positive evidence; when a block cannot be proven dead, it is deferred and recorded, and the phase total shrinks. The budget is a ceiling, not a target.

### D9 — The two new guard specs are the test story, and they are characterization tests

Neither package has a `dead-code-sweep.spec.ts`; the other six do. Adding them keeps the pattern and, more usefully, encodes the KEEP set as executable assertions — `getByMsgType`, `sendKeepAlive`, `waitForAuth`, `categorizeSymbols`, `icon-trade-categories.tsx`, `trade-parameter-presets.ts`, the four `commission` copy sites — so the next sweep cannot delete a duck-typed method on a clean grep.

They pin behaviour that already holds and are written after the deletions they guard, so **they never go red**. Under `.buildwright/framework/tdd-evidence.md` they are declared as characterization tests, not presented as red→green. Every other test change in this sweep is the deletion of a spec whose only subject is deleted in the same commit — also no red to cite. The PR description states both plainly.

## Risks / Trade-offs

- **A deleted export reaches a `.jsx` consumer as `undefined` at runtime with no static warning.** `packages/core` is mostly `.jsx` and outside `tsconfig.json`. → Every deleted symbol gets a repository-wide word-bounded grep including `.js`/`.jsx`; the import line and the call it fed are always removed in the same commit; `npm run test:jest` runs before each phase is committed.
- **The notification chain and the Footer are five-file and six-file atomic deletions.** A partial edit ships a header that cannot render. → Each lands as one commit, closed by a zero-hit grep and a `build --workspace=@deriv/core`.
- **`getByMsgType` is invisible to every static tool in this repo.** A future sweep with a cleaner tool will find it "unused" again. → It is on the KEEP list, in the spec, and asserted by the new core guard spec. `git diff packages/core/src/_common/base/socket_cache.js` must be empty.
- **Half of core's stylesheets are claimed dead.** A wrong deletion is invisible to sass-loader and shows up as an unstyled surface in production. → Base-class rule, SCSS last, defer-and-record when unproven, and the phase total shrinks rather than the evidence bar.
- **`contract-type-info.scss` is live at the start of the change and dead at the end.** Deleting it early leaves the `Description/*` files styleless for the intervening commits. → Phase ordering (D3), stated as a scenario in DCR-043.
- **`baseline:update` against an empty `packages/*/dist` wipes the chunk set.** → `npm run build:all` always runs first; `baseline:update` is the last thing before the PR.
- **`package-lock.json` changes, so the first CI `test` run is expected to time out.** `timeout-minutes: 12` versus a cold npm cache; `gh pr checks` shows it as "fail" while the API reports "cancelled" with zero failed steps. → Expected; re-run once the cache is warm. Test code is not changed to work around it.
- **Only 3 of 11 CI checks run on this PR.** Build Project, TypeScript & Linting, all three Jest groups and the SCA scan are base-filtered out. → Local `build:all`, per-package Jest, both `tsc` oracles and both baseline checks are run by hand and their numbers go in the PR description. GitHub retargets the PR to `master` when #1273 merges, at which point the full matrix runs.
- **Playwright cannot verify any of this in-PR,** and C8c touches trade flows the suite does cover. → The exit criterion is discharged by naming the covering specs under `playwright/tests/trade/` and `playwright/tests/trade-automate/`; no run is claimed.
- **The multi-run protocol is the single biggest failure mode.** A half-ticked plan shipped as complete is the exact outcome the restructure exists to prevent. → Ticks land per phase; the remainder is split into a follow-up issue via `docs/spec-to-pr/deferrals/` and named in the PR description.

## Migration Plan

No data migration and no intended user-facing behaviour change. The one deliberate product change is the cookie banner's removal, decided late Aug 2026; it is already hard-disabled at `app-contents.jsx`, so no user sees a difference.

One behaviour is deliberately _not_ migrated: `pinned_trade_types` in `localStorage` is orphaned by the TradeTypes deletion. No cleanup is written for it — the key is inert, costs bytes, and a migration shim would outlive its purpose. This is stated in the PR description.

Rollback is a plain revert: everything here reverts together as one commit for the whole branch, baselines included. The PR targets `akmal/issue-1273-c8-small`; GitHub retargets it to `master` when #1273 merges. `master` is neither rebased onto nor merged in.
