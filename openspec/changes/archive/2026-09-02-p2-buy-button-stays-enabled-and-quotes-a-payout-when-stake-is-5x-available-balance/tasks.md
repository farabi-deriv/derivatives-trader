## Open Questions

Neither question changes the specs, the approach, or the breakdown below — each has a default already encoded in the tasks, and a reviewer can flip it cheaply. The named task says where.

1. **Demo-account copy at a zero balance.** At `balance <= 0` the reused helper resolves `Balance is empty. Deposit funds to buy this contract.`, which is not literally actionable on a virtual account (it resets rather than deposits).
    - **DEFAULT — keep the shared sentence.** It is pre-existing copy that both stake inputs already show on virtual accounts, and `ServiceErrorSheet` says much the same; adding a virtual-only string would introduce new copy for a rare state, against this change's "no new strings" goal.
    - To change it: branch on `client.is_virtual` in task 3.3 and add the string to the helper. That makes the helper account-aware, which is why it is not the default.

2. **Should the automation Run control get the same gate?** Today **Run** blocks only at `Number(balance) <= 0` (`packages/trader/src/AppV2/Hooks/useRunControls.ts:95-105`), so after this change **Buy** and **Run** apply different balance rules.
    - **DEFAULT — no, leave Run alone.** A run's stake evolves across the session (martingale-style multipliers), so gating on the opening charge is not obviously right, and #1245 is about the Buy control. Recorded in `proposal.md` → **Explicitly unaffected**.
    - To change it: a separate change; nothing in this breakdown needs to move.
