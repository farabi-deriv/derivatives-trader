## Open Questions

### How much of the trade Parameters panel should this change repair?

- [recommended] Duration plus Risk management — the only two desktop parameter chips whose _value_ text is built with the unsubscribed module-level `localize`, which is exactly what issue #960 describes as "the Duration field and some related content in the Parameters section" (`duration-desktop.tsx:470-584`, `risk-management-desktop.tsx:85`; every other chip's value is either `<Localize>` JSX or a number)

### Which signal should re-render the parameter after a language change?

- [recommended] `localize` taken from `useTranslations()` — react-i18next binds it to i18next's `languageChanged` (`react-i18next/dist/es/defaults.js:3`), the only moment at which translated text is actually available, and it is the pattern the already-correct mobile path uses (`duration.tsx:81`)

Both questions proceed on the recommended option; the plan below is complete and implementable as written.
