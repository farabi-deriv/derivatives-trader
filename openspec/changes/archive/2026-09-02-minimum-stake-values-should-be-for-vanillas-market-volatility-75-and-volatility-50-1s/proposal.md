## Why

On Vanillas, DTrader v2 commits a default stake of **USD 2** (`contracts_for.default_stake`) before the market's minimum stake is known, so on markets whose minimum is above 2 — Volatility 25 (1s) `1HZ25V`, Volatility 50 (1s) `1HZ50V`, Volatility 75 `R_75`, and others — the user lands on an invalid stake and a stake error on a fresh load. The static quick picks compound it: on desktop they are rendered with no min/max filtering at all, so the first chips are unusable on those markets.

The root cause is an ordering gap. `min_stake` is not exposed on `contracts_for` (confirmed at `packages/api/types.ts:104-115` — the augmented entry adds only `default_stake` and `payout_choices`); it only lands after a `proposal` round-trip, via `setStakeBoundary`. So the default stake is chosen before the minimum that would validate it exists.

**That gap is not a Vanillas property.** It is the same on every trade type, because `contracts_for` omits the limits for all of them. Turbos hit exactly this bug already and it was papered over with a hardcoded per-symbol table (`STAKE_PRESET_SYMBOL_OVERRIDES` for `1HZ25V`, `1HZ50V`, `R_75`) — the approach this issue explicitly rules out. Fixing it for Vanillas alone would mean shipping the correct derivation next to the hardcoded workaround it supersedes, and leaving Rise/Fall, Higher/Lower, Touch/No Touch, Digits, Accumulators and Multipliers offering quick picks their market would reject. This change therefore implements the derivation **once, for every trade type**.

## What Changes

- **Resolve the market minimum before a stake is surfaced, then derive from it.** The first `proposal` for a given (symbol, contract type) is treated as a **limits probe**: its `min_stake` / `max_stake` are recorded into `stake_boundary`, the default stake and quick picks are re-derived from that minimum, and the corrected stake is re-priced — all before the response is allowed to become user-visible state. A probe that comes back rejecting the probing stake is absorbed, so **no stake error is shown on a fresh load**, on any trade type.
- **Derive the default stake at runtime, no hardcoding.** A pure helper rounds the resolved minimum up to the next round value on a per-decade ladder of `[1, 1.5, 2, 2.5, 3, 4, 5, 6, 8, 10]` (min `6.5` → `8`, min `34.06` → `40`, min `25` → `25`), and the default becomes `max(contracts_for default_stake, rounded_minimum)`. Markets whose API default is already valid keep USD 2 exactly as today; only markets whose minimum exceeds it are bumped. A narrow `[min, max]` band that the rounded value would overshoot falls back to the raw minimum.
- **Quick picks start at the derived default and ascend, on every trade type.** A single `getStakeLadderValues` helper leads with the derived default, keeps the shared presets above it, caps at the market maximum, and tops the row up from above so it is always six wide. This replaces the old `getStakePresetValues` filter, which only prepended the floor when the base presets reached below it — leaving the applied default off the ladder whenever the floor sat under the lowest preset.
- **Desktop and mobile quick picks are made consistent.** `stake-desktop.tsx` previously called `getStakePresets` raw (no limit filtering) and `stake-input.tsx` used its own recovered limits; both now read one store-side value (`stake_preset_limits`), so the two surfaces cannot drift or be a round trip out of step.
- **The invariant holds on every entry into a market**, not just first load: sub-type flips, symbol switches, entering from another trade type, and tab navigation. Reconciliation is keyed per (symbol, contract type), because `stake_boundary` itself is keyed per contract type, so sub-types carry separate minimums.
- **The trade parameters row shows a skeleton until the open tab is priced**, so a newly opened market or trade-type tab never displays values carried over from the tab just left. The placeholder matches the chip's height _and_ its corner radius, so the row neither resizes nor changes shape when the values land.
- **The curated per-symbol table is deleted outright.** `STAKE_PRESET_SYMBOL_OVERRIDES` (and its `getStakePresetOverride` accessor) held hand-written stake lists for the three high-minimum Turbos symbols — the exact "hard-coded values" this issue rules out. With every market deriving its ladder from its own reported minimum, those symbols no longer need an entry, and `getStakePresets` no longer takes a symbol at all. This is what makes the fix a real one rather than a second mechanism living beside the workaround it replaces.
- **Record a stake band from a partial response.** `setStakeBoundary` required both a minimum and a maximum, so a rejection carrying only `min_stake` — which is what Vanillas on Volatility 75 actually returns — was dropped entirely. That single condition is why the reported market never resolved its limits: the quick picks stayed in their loading skeleton, the stake stayed on the rejected default, and the per-key fence meant nothing retried.
- **Absorb the probe even when the stake needs no correcting.** A rejection could otherwise still reach `proposal_info` while the fence blocked any re-price, stranding the platform's own entry stake in an error state with Buy disabled.
- **Not in scope:** asking the backend to expose min stake on `contracts_for`. That is the only option that fully removes the round-trip, but it needs an API change; it is recorded as a follow-up in `design.md` (Risks) so the client-side gate can be simplified once it lands.

## Capabilities

### New Capabilities

- `stake-defaults`: How the default stake and stake quick picks are derived from the market's minimum stake — resolution ordering (minimum before a stake is surfaced), the rounding rule, the quick-pick ladder and its fixed width, the per-(symbol, contract type) re-derivation on every entry into a market, suppression of the transient probe error, desktop/mobile parity, the trade-parameters loading state, and the requirement that the derivation is uniform across trade types rather than gated to one.

## Impact

- **Affected code**
    - `packages/trader/src/AppV2/Utils/trade-params-utils.tsx` — `roundUpToRoundStake(min)` (per-decade `[1, 1.5, 2, 2.5, 3, 4, 5, 6, 8, 10]` ladder), `getDerivedDefaultStake(api_default_stake, min_stake, max_stake)` and `getStakeLadderValues(base_presets, floor, max_stake)`. The older `getStakePresetValues` is **deleted**: both surfaces moved to the ladder, leaving it with no production caller.
    - `packages/trader/src/Stores/Modules/Trading/trade-store.ts` — `absorbStakeLimitsProbe`, the limits-probe absorb + reconcile step called from `onProposalResponse` before the `proposal_info` / `validation_params` writes, applied to every trade type; the `probed_stake_keys` per-market re-entrancy fence and provenance set; the market-qualified `stake_boundary`; the `stake_preset_limits` computed both stake surfaces read; and the `default_stake` reset block applying the derived default. The trade-parameters loading state rides the existing `is_awaiting_contracts_for` hold (armed on market switch, released by `processContractsForV2`).
    - `packages/trader/src/Stores/Modules/Trading/Helpers/proposal.ts` — `getStakeLimitsFromResponse`, the one place that knows where responses carry the stake band (proposal payload, `error.details`, or `code_args` on `InvalidMinStake`), beside the other response utilities.
    - `packages/trader/src/AppV2/Components/TradeParameters/Stake/stake-desktop.tsx` and `stake-input.tsx` — both consume `stake_preset_limits` and the shared ladder helper; each dropped its own trade-type branch.
    - `packages/trader/src/AppV2/Components/TradeParameters/Shared/trade-param-skeleton.tsx` + `trade-parameters.scss` — the chip placeholder, now carrying quill's field corner radius as well as its height.
    - `packages/trader/src/AppV2/Components/InputPopover/value-chips-skeleton.tsx` — the quick-pick row placeholder.
    - `packages/trader/src/AppV2/Config/trade-parameter-presets.ts` — `STAKE_PRESET_SYMBOL_OVERRIDES` and `getStakePresetOverride` **deleted**; `getStakePresets` no longer takes a symbol.
    - `packages/stores/src/mockStore.ts` — a `stake_preset_limits` default so component tests render chips rather than the loading state.
- **Affected tests** — helper units (`trade-param-utils.spec.tsx`), store behaviour including the cross-trade-type reconciliation (`trade-store.spec.ts`), both stake surfaces (`stake.spec.tsx`), the parameters row loading state (`trade-parameters.spec.tsx`), the two skeletons, and the config characterization guard (`trade-parameter-presets.spec.ts`).
- **Behaviour change beyond the reported bug:** a customised stake is no longer carried across a market or trade-type switch on **any** trade type (previously only Vanillas force-reset). Carrying a high stake into a low-minimum market is what made an entry stake look like a value the user never chose, so the reset is applied uniformly.
- **The three previously-curated Turbos symbols get derived ladders**, close to but not identical to the deleted tables: `1HZ25V` `[40, 50, 60, 80, 100, 150]` against `[35, 40, 45, 50, 55, 60]`, `1HZ50V` `[25, 40, 50, 80, 100, 150]` against `[25, 30, 35, 40, 45, 50]`, `R_75` `[8, 10, 15, 25, 40, 50]` against `[10, 15, 20, 25, 30, 35]`. Each still opens at or near the market minimum; the derived rows reach further above it than the hand-written ones did.
- **No API or dependency changes.** New observables on `TradeStore`: `probed_stake_keys` (the per-market probe fence) and the `stake_preset_limits` computed; the trade-parameters loading state reuses the existing `is_awaiting_contracts_for`. `stake_boundary`'s keys become market-qualified (`` `${symbol}:${contract_type}` ``) — it is store-internal state with no external reader, so nothing outside the store changes shape. No feature flag, no migration.
