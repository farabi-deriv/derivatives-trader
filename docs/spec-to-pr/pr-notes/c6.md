# PR notes — c6 (Fix the 16 bugs the audits surfaced)

Content for the pull request description. Ref: derivatives-trader issue #1271 (C6).

## Bug 11 (ABF-012) — dead cookie cluster removal, provenance

`client-store.js` carried a dead chain, all frozen at their defaults:

- `setEmail` had **zero callers**, so `email` was permanently `undefined`.
- The constructor `reaction` fired `setCookieAccount()`, which — because `email` was always
  falsy — only ever took its `else` branch: `removeCookies('region', 'client_information')` and
  `has_cookie_account = false`. The `if` branch (the `Cookies.set('region', …)` /
  `Cookies.set('client_information', …)` writes) was never reachable.
- `has_cookie_account` was therefore permanently `false`.

The whole cluster (`email`, `setEmail`, `setCookieAccount`, `has_cookie_account`, the constructor
reaction, and the now-orphaned `getRegion` / `getTrustedDomainName` imports) is deleted. `Cookies`
and `removeCookies` are kept — still used by the `utm_data` reader and the `options_account_id`
cleanup respectively.

The `region` / `client_information` cookie writes were only ever reachable from the dead `if` branch,
so the cookies were never actually written by this code. `@deriv/shared`'s `analytics.ts`
`processEvent` does _read_ `client_information`, but (a) it was never written, so the read is a no-op,
and (b) even a read `email` is deleted from the event immediately afterward — so the removal has no
observable effect. This rests on the recorded human confirmation that no property depends on those
cookies being written.

## Bugs 11 & 12 (ABF-012 / ABF-013) — Analytics notes (informational)

- **App-mount `Analytics.reset()` (bug 11 fallout).** The old effect in `app.jsx` was
  `if (!client.email) Analytics.reset()` with deps `[client.email]`. Since `email` was always
  `undefined`, it fired exactly once on mount. Removing `email` would strand the effect, so it is
  replaced by an unconditional `Analytics.reset()` on mount (deps `[]`) — **identical observable
  behaviour**. Whether reset-on-every-mount is the _intended_ trigger is out of scope for this
  dead-code batch and is tracked in
  `docs/spec-to-pr/deferrals/analytics-reset-on-mount-email-gate.md`.
- **GTM `email` field (bug 11 fallout).** `gtm-store.js` pushed `email: client.email` inside the
  logged-in datalayer block; because `email` was always `undefined` the field carried `undefined`.
  It is removed — no change to what GTM actually received.
- **GTM `chart_asset_info` (bug 12 / ABF-013).** `is_chart_asset_info_visible` was commented out and
  read `undefined`; the GTM field now carries the constant `'hidden'` it always resolved to, and the
  dead commented ui-store block plus its `local_storage_properties` string are removed.

## Red evidence (bug 11)

`Red: [ABF-012] no longer exposes setEmail, setCookieAccount, has_cookie_account or email` —
against the unfixed store, `setEmail`/`setCookieAccount` were `action.bound` functions and
`has_cookie_account` was `false`, so the `toBeUndefined()` assertions failed; they pass after the
cluster is deleted. The app-mount `Analytics.reset()` test is a **characterization** test (behaviour
preserved, never red).
